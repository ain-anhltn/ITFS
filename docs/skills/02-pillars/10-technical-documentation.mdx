# Technical Documentation

> **Vẽ rõ ràng. Viết mạch lạc. Từ ghi chép đến truyền đạt kiến trúc hệ thống.**

## Lộ trình học 9 giai đoạn

| #   | Giai đoạn                                | Nội dung                                                                                 | Trọng tâm |
| --- | ---------------------------------------- | ---------------------------------------------------------------------------------------- | --------- |
| 1   | **Documentation Basics**                 | Sơ đồ cơ bản (flowchart, ERD), meeting/task notes, công cụ (Confluence, Notion, draw.io) | J1        |
| 2   | **Documentation Principles**             | Đọc hiểu specs và diagram, độ chính xác, rõ ràng — thiếu tài liệu là rủi ro              | J1 – J2   |
| 3   | **Technical Notes & Setup Docs**         | Activity diagram, database diagram, README, setup guide dùng được                        | J2 – J3   |
| 4   | **Design & Decision Documentation**      | Class, component, sequence diagrams, API docs, ADR                                       | J3 – M1   |
| 5   | **Architecture Communication**           | Architecture, infrastructure, state machine diagrams, solution proposals                 | M1 – M2   |
| 6   | **Project Documentation Architecture**   | Documentation standards, knowledge base, review process                                  | M2 – M3   |
| 7   | **Cross-Project Knowledge Strategy**     | System design docs, chất lượng viết, best practices, knowledge management                | M3 – S1   |
| 8   | **Documentation Governance & Platforms** | Documentation standards, tools & platforms, technical writing excellence                 | S1 – S2   |
| 9   | **Enterprise Knowledge Vision**          | Documentation frameworks, KM systems, AI-augmented workflows                             | S2 – S3   |

## Junior

### J1 · Remember

- **Giai đoạn trọng tâm:** Documentation Basics, Documentation Principles
- **Chủ đề cốt lõi:** Diagrams, meeting notes, task notes. Documentation tools: Confluence, Notion, draw.io. Specs, đọc diagram, độ chính xác, rõ ràng.
- **Vì sao:** Tri thức dùng chung bắt đầu từ tri thức được ghi lại. Tư duy không được tài liệu hóa tạo rủi ro giao hàng.
- **Hành vi:** Nhận biết và đọc được các sơ đồ cơ bản (flowchart, ER). Ghi meeting/task notes rõ ràng. Biết dùng Confluence, Notion, draw.io. Hiểu technical specs.
- **AI:** Dùng AI nháp notes nhưng nhận biết tài liệu AI sinh có thể chứa thông tin sai.
- **Tham chiếu:** P1

### J2 · Understand

- **Giai đoạn trọng tâm:** Documentation Principles, Technical Notes & Setup Docs
- **Chủ đề cốt lõi:** Specs, đọc diagram. Độ chính xác, rõ ràng. Activity diagram, DB diagram. README, setup guides, technical notes.
- **Vì sao:** Tư duy không được tài liệu hóa tạo rủi ro giao hàng. Implementation cần tài liệu dùng được.
- **Hành vi:** Hiểu vì sao tài liệu quan trọng. Đọc và giải thích technical diagrams/specs. Viết technical notes, README và setup guide dùng được.
- **AI:** Review độ chính xác của tài liệu AI sinh. Nhận biết nội dung "nghe hay" nhưng sai thực tế.
- **Tham chiếu:** P3

### J3 · Understand → Apply

- **Giai đoạn trọng tâm:** Technical Notes & Setup Docs, Design & Decision Documentation
- **Chủ đề cốt lõi:** Activity, database diagrams. README, setup guides. Class, component, sequence diagrams. API docs, ADR.
- **Vì sao:** Implementation cần tài liệu dùng được. Hệ thống phức tạp cần quyết định được ghi rõ.
- **Hành vi:** Vẽ activity diagram, database diagram. Viết README/setup guide. Tạo class, component, sequence diagrams và API docs. Ghi lại quyết định kỹ thuật bằng ADR.
- **AI:** AI có thể nháp khung tài liệu, nhưng kỹ sư kiểm tra mọi chi tiết kỹ thuật. Tài liệu phải phản ánh implementation và lý do thật.
- **Tham chiếu:** V1

## Middle

### M1 · Apply

- **Giai đoạn trọng tâm:** Design & Decision Documentation, Architecture Communication
- **Chủ đề cốt lõi:** Class, component, sequence diagrams. API documentation, ADR. Architecture, infrastructure diagrams. State machine diagrams, solution proposals.
- **Vì sao:** Hệ thống phức tạp cần quyết định được ghi rõ. Tài liệu tốt giúp team thống nhất nhanh.
- **Hành vi:** Tạo tài liệu đầy đủ cho feature/system. Vẽ architecture, infrastructure, state machine diagrams. Viết proposals. ADR phải thể hiện lý do thực tế.
- **AI:** AI tạo khung, kỹ sư chịu trách nhiệm chi tiết chính xác. Không chấp nhận tài liệu chỉ đúng hình thức.
- **Tham chiếu:** P4

### M2 · Apply → Analyze

- **Giai đoạn trọng tâm:** Architecture Communication, Project Documentation Architecture
- **Chủ đề cốt lõi:** Architecture, infra, state machine diagrams. Solution proposals. Documentation standards, knowledge base. Review process.
- **Vì sao:** Tài liệu tốt giúp team thống nhất nhanh. Dự án cần hệ thống tài liệu bền vững.
- **Management:** Nhận diện documentation gaps. Review chất lượng và tính nhất quán của tài liệu trong team/project.
- **Expert:** Tạo architecture, infrastructure, state machine diagrams và solution proposals để stakeholders hiểu nhanh.
- **AI:** Đánh giá tài liệu AI sinh còn thiếu gì so với tài liệu của kỹ sư nhiều kinh nghiệm.
- **Tham chiếu:** P4

### M3 · Analyze

- **Giai đoạn trọng tâm:** Project Documentation Architecture, Cross-Project Knowledge Strategy
- **Chủ đề cốt lõi:** Documentation standards. Knowledge base, review process. System design docs. Chất lượng viết, best practices, knowledge management.
- **Vì sao:** Dự án cần hệ thống tài liệu bền vững. Quy mô lớn cần ngôn ngữ chung và tái sử dụng.
- **Management:** Xây documentation standards và chiến lược knowledge base. Định nghĩa review process để giữ chất lượng tài liệu.
- **Expert:** Viết solution proposals phức tạp cho khách hàng/stakeholders. Đạt ≥ 4 solution proposals/năm.
- **AI:** Tài liệu AI sinh phải chính xác trước khi publish. Thiết lập review process bắt buộc.

## Senior

### S1 · Analyze → Evaluate

- **Giai đoạn trọng tâm:** Cross-Project Knowledge Strategy, Documentation Governance & Platforms
- **Chủ đề cốt lõi:** System design documentation. Best practices, knowledge management. Documentation standards, tools & platforms. Technical writing excellence.
- **Vì sao:** Quy mô lớn cần ngôn ngữ chung và tái sử dụng. Department cần nền tảng tài liệu đáng tin cậy.
- **Management:** Quản trị tài liệu trên nhiều dự án. Thúc đẩy knowledge management và thực hành tài liệu dùng chung.
- **Expert:** Thiết lập chất lượng technical writing, best practices. Review/phê duyệt tài liệu system design.
- **AI:** Đánh giá và chuẩn hóa độ chính xác của tài liệu AI trên nhiều dự án.
- **Tham chiếu:** P4

### S2 · Evaluate

- **Giai đoạn trọng tâm:** Documentation Governance & Platforms, Enterprise Knowledge Vision
- **Chủ đề cốt lõi:** Documentation standards. Tools & platforms. Technical writing excellence. Documentation frameworks, KM systems.
- **Vì sao:** Department cần nền tảng tài liệu đáng tin cậy. Tri thức trở thành năng lực của tổ chức.
- **Management:** Xây documentation standards cấp department. Định hướng đầu tư nền tảng knowledge management.
- **Expert:** Nâng technical writing excellence. Chọn và phát triển tools/platforms cho tài liệu và KM.
- **AI:** Xây chuẩn cho tài liệu có AI hỗ trợ ở cấp department, đặc biệt về độ chính xác, truy vết và review.

### S3 · Evaluate → Create

- **Giai đoạn trọng tâm:** Enterprise Knowledge Vision
- **Chủ đề cốt lõi:** Documentation frameworks. Knowledge management systems. AI-augmented workflows. Chiến lược tri thức của tổ chức.
- **Vì sao:** Tri thức trở thành năng lực của tổ chức.
- **Management:** Xây chiến lược knowledge management cấp tổ chức. Biến tài liệu thành một phần của hệ thống tri thức tổ chức.
- **Expert:** Sáng tạo documentation frameworks và KM systems mở rộng được cho toàn tổ chức.
- **AI:** Kiến tạo workflow tài liệu có AI hỗ trợ: sinh, kiểm chứng, truy xuất và duy trì tri thức liên tục.
